# 02 命名契约

## 适用范围

本文件规定脚本名、工具文件名与配置文件名之间的对应关系。它的目的只有一个：让人从任意一端出发，不检索也能写出另外两端的名字。规则编号形如 `N-01`。

本文件不规定函数名、变量名与提交信息格式。

## 1 三元组

命名契约的核心是一个三元组：

```text
package.json 的 <verb>:<topic>
  <-> tools/<verb>-<topic>.mjs
  <-> governance/<topic>.json（当该工具读取配置时）
```

- **N-01**　每一条 `<verb>:<topic>` 形式的脚本必须恰好对应一个 `tools/<verb>-<topic>.mjs`；缺少任一端的名字禁止出现。[[machine]]
- **N-02**　`<topic>` 必须是小写短横线连接的名词短语，且在同一动词下唯一。[[machine]]
- **N-03**　一个读取配置的工具，其配置文件必须命名为 `governance/<topic>.json`，`<topic>` 与工具的 `<topic>` 逐字相同。[[machine]]

## 2 动词词表

| 动词      | 含义                                 |
| --------- | ------------------------------------ |
| `verify`  | 只读检查，以退出码给出通过／失败结论 |
| `build`   | 产出确定性生成物                     |
| `analyze` | 产出供人阅读的报告，不给出通过／失败 |

- **N-04**　动词必须取自上表；新增一个动词必须先修改本表，禁止在脚本里直接使用表外动词。[[machine]]
- **N-05**　`verify` 开头的工具禁止写入仓库内任何文件；需要写入的检查必须拆成一个 `verify` 工具与一个 `build` 工具，或以显式的写入模式暴露（见 N-06）。[[machine]]

## 3 模式脚本

- **N-06**　同一个工具的不同运行模式必须命名为 `<verb>:<topic>:<mode>`，其中 `<mode>` 是该模式的命令行参数去掉前导短横线后的名字。[[machine]]

`verify:doc-facts:write` 对应 `node tools/verify-doc-facts.mjs --write` 就是这条规则的样例。这个命名让「有一个会写文件的模式」在脚本列表里直接可见，而不是藏在工具源码里。

## 4 改名

- **N-07**　已经被下游引用的脚本名与工具名禁止改名；确需改名时必须先有一份状态为已接受的 ADR，并在同一次变更里保留旧名作为别名至少一个发布周期。[[review]]

改名的代价不在本仓库，而在所有引用它的持续集成配置里，那些配置在本仓库看不见。

## 变更影响

修改第 1 节的三元组会使 `package.json` 的 `scripts` 与 `tools/` 下全部文件名同时需要修订。修改第 2 节的动词词表会改变 N-04 的判定集合。修改 N-03 会改变 `tools/` 下每一个工具查找配置的默认路径。
