# 06 ADR 治理

## 适用范围

本文件规定架构决策记录（ADR）的适用场合、编号、状态生命周期与评审规则。它约束决定的记录形式，不约束决定的内容。规则编号形如 `A-01`。

本文件不适用于代码注释、提交信息与聊天记录里的临时说明；那些不构成决定。

## 1 什么时候写 ADR

以下五类变更在实施之前先要有一份状态为「已接受」的 ADR：

1. 对本规范集第一层原则的任何改动；
2. 对目录布局总表或顶层目录集合的任何改动；
3. 对命名契约三元组的任何改动；
4. 对工具链的任何改动：引入或移除运行时、类型检查器、测试运行器、格式化器，或引入任何运行时依赖；
5. 任何约束下游消费者的决定：取得形态、版本与废弃策略、公共面的增减。

- **A-01**　上列五类变更必须先有一份状态为已接受的 ADR，禁止先改文档或代码再补写 ADR。[[review]]
- **A-02**　错别字、措辞澄清、不改变任何规则语义的重排，不需要 ADR；把它们写成 ADR 会稀释这套记录的信号。[[review]]

## 2 编号

- **A-03**　ADR 文件名必须是 `NNNN-<kebab-case-标题>.md`，`NNNN` 为四位十进制，从 `0001` 起单调递增。[[machine]]
- **A-04**　编号一经分配禁止复用，即使该 ADR 后来被废弃或被取代。[[machine]]
- **A-05**　并发提案取号冲突时，后合并者必须改号；禁止出现两份同号 ADR。[[machine]]

## 3 状态生命周期

```text
提议 ──► 已接受 ──► 已废弃
              │
              └──► 被取代（由 ADR-NNNN）
```

| 状态       | 含义                           | 允许的后续     |
| ---------- | ------------------------------ | -------------- |
| **提议**   | 已成文、待评审，尚未生效       | 已接受；或撤回 |
| **已接受** | 现行有效，文档与代码与之一致   | 已废弃；被取代 |
| **已废弃** | 约束的对象已消失，且无替代决定 | 终态           |
| **被取代** | 被一份新的已接受 ADR 替换      | 终态           |

- **A-06**　状态取值必须取自上表四项；被取代者的状态行必须写明取代它的 ADR 编号。[[machine]]
- **A-07**　处于提议状态的 ADR 禁止被引用为已确立的结论，也禁止据以实施。[[review]]
- **A-08**　已接受、已废弃、被取代三种状态的 ADR 禁止被编辑正文；改变一个决定的方式只有新写一份 ADR 并取代旧的。允许的例外是修正笔误与补写「被取代」指针。[[review]]
- **A-09**　新 ADR 取代旧 ADR 时必须双向链接：新 ADR 写明取代了谁，旧 ADR 的状态行写明被谁取代。[[machine]]

## 4 评审

- **A-10**　智能体可以起草 ADR，但禁止自行把任何一份 ADR 的状态标记为「已接受」，也禁止代填批准人字段。批准是仓库所有者本人的动作。[[owner]]
- **A-11**　一份 ADR 的「备选方案及其否决理由」一节禁止为空，也禁止只写「无」。至少记录一个真实被考虑过并被否决的方案及其否决理由。[[machine]]
- **A-12**　涉及数值证据的 ADR，其背景一节必须按 `05-DOCUMENTATION.md` 第 3 节的三段式给出可复现的度量方式，禁止只给结论数字。[[review]]

A-10 是本文件最容易被绕过的一条，绕过的方式通常不是明目张胆地改状态，而是在别处写下「该方案已确定」并据此实施。A-07 与 A-10 合起来堵这个口子。

## 5 法律事项

- **A-13**　ADR 禁止给出法律结论。凡涉及权利、许可、合规的问题，一律作为待人工决策的输入写入背景或后果一节。[[owner]]

## 变更影响

修改第 1 节的五类清单会改变哪些变更需要事前授权，属于第一类变更，需要它自身的 ADR。修改第 3 节的状态表会使既有 ADR 的状态行需要逐份复核。修改 A-10 会改变智能体在本仓库的权限边界。
