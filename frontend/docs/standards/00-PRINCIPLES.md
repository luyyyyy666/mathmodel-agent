# 00 治理原则

## 适用范围

本文件是本规范集的第一层。它约束的对象是「门禁」——任何以退出码给出通过／失败结论的检查程序——以及这些门禁所依据的规范文本本身。本文件不约束被检查的业务代码怎么写。

其余七份文件在本文件之下：当某条具体规则与本文件冲突时，以本文件为准，并且这一冲突本身就是一处需要修订的缺陷。本文件的规则编号形如 `P-01`。

## 1 门禁的独立性

- **P-01**　门禁在只有仓库文本、没有任何构建产物的前提下必须能够跑完并给出结论；它禁止依赖构建目录、证据目录、生成索引、版本控制历史或网络。[[machine]]
- **P-02**　门禁的每一条失败必须指名位置：`文件:行号`，或在没有行的场合指名文件与条目键。只说「有 3 处不合规」的失败信息禁止出现。[[machine]]
- **P-03**　门禁禁止把「没有检查」表述为「检查通过」。凡是它无法判定的对象，必须在摘要里单列为未校验并计数，禁止折算进已校验数。[[machine]]

P-01 的理由是可复述的：一道只在完整环境里才能跑的门禁，第一次在干净检出上崩溃之后就会被关掉，此后它守护的东西无人守护。P-03 的理由是同一个方向的：一个把未校验计入已校验的摘要，比没有摘要更危险，因为它让读者停止怀疑。

## 2 结论的形态

- **P-04**　门禁的退出码是它唯一的结论；任何解读禁止与退出码相反。0 表示「本次检查的全部对象都通过」，非 0 表示「至少一处未通过」。[[machine]]
- **P-05**　当被检查的对象不存在——空仓库、空配置、尚未声明任何规则——门禁必须打印一条说明其检查范围为空的 `ok - ` 摘要并以 0 退出，禁止崩溃，也禁止以「无法确定」为由报失败。[[machine]]

P-05 是一条容易被写反的规则。新仓库正是引入门禁的时刻，而这时它没有任何可检查的内容；一道在这个状态崩溃的门禁没有机会被采用。

## 3 规范文本自身的约束

- **P-06**　规范集中每一条规范性语句必须在行末带上四类验证标记之一，声明这条规则靠什么手段落实。[[machine]]
- **P-07**　标记为 `[[owner]]` 的事项只由仓库所有者本人做出结论；智能体禁止代为决定，也禁止宣布该事项已完成，至多准备材料。[[owner]]
- **P-08**　本规范集与其门禁禁止给出法律结论。凡涉及权利、许可、合规的问题，一律作为待人工决策的输入记录，不在此处判定。[[owner]]

四类标记的完整定义在 `05-DOCUMENTATION.md` 的标记体系一节，本节只声明标记这一项义务，不重复定义。

## 4 规则的可反驳性

- **P-09**　每条规则必须写出它防止的具体故障；写不出该故障的规则必须删除，而不是保留为惯例。[[review]]
- **P-10**　当一条规则与实测事实冲突时，先修订规则文本或如实记录该冲突，禁止改写实测值使其符合规则。[[review]]

## 变更影响

修改本文件会改变其余七份文件的判读基准，因此每一次修改都落在 ADR 的第一类变更里（见 `06-ADR-GOVERNANCE.md`）。删除或放宽 P-01、P-03、P-05 中的任何一条，会使四道门禁的实现同时失去依据，需要连同 `tools/` 下对应工具一并修订。
