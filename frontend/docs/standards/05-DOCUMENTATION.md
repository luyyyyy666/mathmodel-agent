# 05 文档写法

## 适用范围

本文件规定 `docs/` 下规范文档的骨架、标记体系、引用写法，以及实测值的写法。它不规定文风、篇幅与语言。规则编号形如 `D-01`。

本文件是四道门禁里两道的规则来源：`tools/verify-spec-consistency.mjs` 执行第 1、2、4 节，`tools/verify-doc-facts.mjs` 执行第 3 节。

## 1 骨架

- **D-01**　每份规范文档必须以 `## 适用范围` 作为第一个二级小节开篇，以 `## 变更影响` 作为最后一个二级小节收尾。[[machine]]
- **D-02**　`适用范围` 必须写出本文件约束什么、不约束什么；`变更影响` 必须写出改动本文件会波及哪些文件与哪些门禁。[[review]]

一份不声明适用范围的规范，会被引用去管它从未打算管的事；一份不声明变更影响的规范，会被一个看不见后果的人修改。这两节的内容不带标记，因为它们陈述范围而不施加义务。

## 2 标记体系

每一条规范性语句的行末带一个方括号标记，声明这条规则靠什么落实。

| 标记          | 含义                                       | 谁可以宣布它满足                       |
| ------------- | ------------------------------------------ | -------------------------------------- |
| `[[machine]]` | 存在一条命令给出确定的通过／失败判定       | 脚本的退出码即结论                     |
| `[[review]]`  | 判断需要读代码或文档，无法归约为一条命令   | 智能体先自评，最终确认权在人类评审者   |
| `[[owner]]`   | 涉及授权、对外承诺、批准签字               | 只有仓库所有者本人，智能体至多准备材料 |
| `[[task]]`    | 不是待校验的规则，而是一件待完成的工程工作 | 完成该工作并通过其自身验收标准的人     |

- **D-03**　规范文档中每一条含有情态词的语句必须带上表四个标记之一；判定顺序是自上而下命中即停。[[machine]]
- **D-04**　`[[owner]]` 与 `[[review]]` 的区别在于智能体的角色：`[[review]]` 允许智能体给出待复核的自评结论，`[[owner]]` 不允许智能体给出结论本身。[[owner]]

标题行、只含粗体标签的行、表头行，以及 `适用范围` 与 `变更影响` 两节的正文，不是规范性语句，不需要标记。这四类排除由门禁按结构判定，不按文件名开列白名单。

## 3 易失实测值的三段式

一处写进文档的实测数字，从落笔那一刻起就在过期。文档不能阻止它过期，能做的是让读者知道它是一次快照，并且知道怎么取到当前值。

- **D-05**　凡在文档中写下实测值，必须以三段式出现：**性质陈述**（这是一个易失量，它为什么会变）、**形如 `YYYY-MM-DD` 的日期**、**重跑命令**。三者缺一即为违规。[[review]]
- **D-06**　禁止写下没有日期、没有重跑命令的裸实测值，也禁止把某一次的计数当作固定事实在别处引用。[[review]]
- **D-07**　被 `tools/verify-doc-facts.mjs` 守住的实测值必须在 `governance/doc-facts.json` 里登记为一条锚点；未登记的实测值只受 D-05 约束，不受门禁保护，这一区别必须在文中写明。[[machine]]
- **D-08**　登记为探针的命令必须是只读命令。门禁会反复运行它，在写入模式下会在一次运行里运行多次，并且无法分辨测量与修改。[[review]]

三段式的样例是下面这一段，它同时是本仓库真实的锚点：

**性质陈述**——本规范集的文档份数、门禁工具个数与规范目录的总字节数都是易失量：增删任何一份文档或任何一个工具都会改变它们，而字节数还会被本段自身的改写改变。引用当前值时重跑下面的命令，不要照抄本段写过的数字。

**快照**——2026-08-28 实测：规范文档 9 份，门禁工具 5 个，`docs/standards/` 合计 30328 字节。

**重跑命令**——

```sh
ls docs/standards/*.md | wc -l
ls tools/*.mjs | wc -l
cat docs/standards/*.md | wc -c
```

上面三个数字与这三条命令的输出由 `npm run verify:doc-facts` 逐次比对，任一处不相等即以非零码退出。字节数是一个自指量：改写它会改变它。写入模式因此是一个不动点循环，它测量、回写、再测量，直到某一轮不再写入任何东西为止。等位数替换不改变文件长度，因此不动点存在；改变位数的替换多花一轮。

## 4 引用

- **D-09**　引用仓库内其他文档的具体位置时必须写成 `路径:行号`，并且在同一行内给出可校验的声明：把被引内容用引号原样引出，或写出被引行携带的稳定编号。[[machine]]
- **D-10**　只写路径而不写行号的引用允许存在，它声明的是「这份文档相关」而不是「这一行说了什么」，禁止把它当作后者使用。[[review]]

D-09 的理由是：只剥掉行号再检查路径存在的检查器，对每一个漂移过的行号都报通过，并且把「检查了路径」在摘要里写成「检查了引用」。带声明的引用让行号可被真正校验；无法校验的引用由门禁单列为未校验，不计入已校验。

本文件的标记体系不新设原则，它落实的是 P-06，原文在 `docs/standards/00-PRINCIPLES.md:26`。

## 变更影响

修改第 2 节的标记表会改变 `governance/spec-consistency.json` 的 `markerPattern`，并使全部既有文档的标记同时需要复核。修改第 3 节会改变 `governance/doc-facts.json` 的锚点模板。修改 D-09 会改变 `tools/verify-spec-consistency.mjs` 的 group B 判定，并可能使既有引用批量失效。
