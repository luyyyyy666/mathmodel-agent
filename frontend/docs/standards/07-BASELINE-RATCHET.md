# 07 基线棘轮

## 适用范围

本文件规定「已经存在、无法在一次变更里修完的失败」如何被记录、比对与偿还。它约束债务台账的形态与判定语义，不规定哪些债务值得偿还。规则编号形如 `G-01`。

本文件与 `governance/gate-baselines.json` 成对使用：本文件写规则，该文件写这个仓库的具体台账。

## 1 问题

一道在干净检出上就失败、而且失败原因不能归咎于任何一次变更的检查，只有三种结局。原样在持续集成里跑，于是每一个变更从第一天起就是红的，一周之内它被关掉。干脆不跑，于是债务无人观测地增长。或者把既有失败集合逐条写下来，此后只对「与记录不符」报错——这就是棘轮。

- **G-01**　基线必须存放在数据文件里，禁止内嵌进检查工具的源码。[[machine]]
- **G-02**　基线数据文件禁止由任何工具自动重写；台账只允许经由人可评审的差异变化。[[machine]]

G-02 的理由很直接：一旦「重新生成基线」是一条命令，接受一个新违规也就是一条命令，而门禁停止发挥作用的那一刻不会有任何提示。

## 2 四个方向

| 方向     | 情形                   | 处置                               |
| -------- | ---------------------- | ---------------------------------- |
| `NEW`    | 观测到的条目不在台账里 | 失败：修好它，而不是把它写进台账   |
| `GROWN`  | 观测计数高于台账记录   | 失败：修好新增的那一处，不抬高数字 |
| `SHRUNK` | 观测计数低于台账记录   | 失败：在同一次变更里调低数字       |
| `GONE`   | 台账条目已不再失败     | 失败：在同一次变更里删除该条目     |

- **G-03**　四个方向必须一律报失败。在改善方向上放行会让台账悄悄过期，而过期的台账会掩盖下一次回归。[[machine]]
- **G-04**　台账条目的身份必须是「键 + 计数」；键禁止使用行号，因为行号会随无关编辑移动，而债务的身份不会。[[machine]]
- **G-05**　新出现的违规禁止通过追加台账条目来消解。[[review]]
- **G-06**　修复一处债务与删除或调低它的台账条目必须发生在同一次变更里。[[machine]]

## 3 台账的可读性

- **G-07**　每一个受棘轮保护的门禁必须在数据文件里写明它的取值命令与解析规则，使任何人重跑一次即可复现观测集合。[[machine]]
- **G-08**　台账条目的总量应当随时间单调下降；连续多次变更中它只增不减时，需要一次专门的偿还，而不是继续追加。[[review]]

## 4 与其他门禁的关系

棘轮不判断违规是否严重，它只断言「记录的债务恰好等于存在的债务」。判断严重性是评审的事。

- **G-09**　棘轮门禁禁止被用来替代它所包裹的那道检查；包裹关系必须在数据文件的说明字段里写明。[[review]]

## 变更影响

修改第 2 节的四个方向会改变 `tools/verify-gate-baselines.mjs` 的比对语义。修改 G-01 或 G-02 会与 `01-REPOSITORY-LAYOUT.md` 的 L-04、L-05 直接冲突，两处需要同一次修订。
